# FNAL-QCDecoding-FPGA

*Created: 2026-07-14 | Last updated: 2026-08-04*

**RCNN Architecture:** the reference architecture Sarıca (https://github.com/usarica/FNAL-QCDecodingTests)  
**Advisor:** Gabriel Perdue (https://github.com/gnperdue/FNAL-QCDecodingTests)  
**hls4ml:** Giuseppe Di Guglielmo (https://github.com/fastmachinelearning/hls4ml)

This repo contains the quantization pipeline, evaluation methodology, and
hls4ml/FPGA-deployment characterization built on top of the RCNN architecture.
The decoder architecture itself is documented in the upstream repo above; what is
new here is everything downstream of it.

## Setup

The environment is a [uv](https://docs.astral.sh/uv/) virtual environment living in
the repo, not conda:

```bash
uv sync
source .venv/bin/activate
```

Or call the interpreter directly without activating, which is what the EAF driver
scripts do:

```bash
.venv/bin/python train_one.py --help
```

**TensorFlow is pinned to 2.15 and must stay there.** Keras 3 (TF 2.16+) removed the
`Layer`/`add_weight` behaviour the decoder's custom layers rely on, and dropped
`nest.is_sequence`, which QKeras 0.9's `QGRU`/`QLSTM` still call. Python is held at
3.11 for the same reason — TF 2.15 has no 3.12 wheels. Several scripts assert the
version at import and fail loudly rather than producing quietly wrong numbers.

## Data

Training pools and evaluation tails are Stim-generated and are **not** committed —
they are tens of GB. Regenerate them with `generate_pools.py` (training pools) and
`make_fresh_tail.py` (held-out tail). Both take a fixed generation seed and record
it, so a regenerated pool is identical to the original.

One exception is committed:
`experiment_log/results_snapshot/eaf/rcnn_threshold/pools/data_d5_p0.010_r3_TAIL200k.npz`
— the fixed 200k evaluation tail (gen-seed 43). Every logical error rate reported in
this repo is scored against these exact shots, so without it the numbers can be
re-run but not reproduced.

## What the main files do

**Data generation**

| file | what it does |
|---|---|
| `generate_pools.py` | Stim-samples the training pools, and computes the deterministic MWPM baseline once per (d, p) at generation time |
| `make_fresh_tail.py` | builds the held-out 200k evaluation tail on a separate generation seed, disjoint from training |
| `gen_pool_r5.py` | generates the d=5, r=5 pool (rounds = d convention) |

**Training**

| file | what it does |
|---|---|
| `train_one.py` | trains one full-precision decoder at one training-set size |
| `train_one_quantized.py` | the quantization-aware equivalent; sets the TF determinism flags before importing TensorFlow |
| `CNNModel_quantized.py` | the quantized model build. `CNNModel.py` is the upstream architecture and is kept byte-for-byte pristine |
| `train_student.py` | trains the distilled student against cached teacher probabilities |
| `StudentModels.py` | the hls4ml-synthesizable student architectures (MLP and GRU) |
| `dump_teacher_probs.py` | caches the frozen teacher's per-shot probability and logit over a pool, so student training is a plain supervised fit |

**Evaluation and analysis**

| file | what it does |
|---|---|
| `eval_on_tail.py` | scores a saved model on the evaluation tail. `--mcnemar` runs the paired test against MWPM; `--dump-per-shot` writes per-shot outcomes for failure analysis |
| `profile_ranges.py` | per-tensor min/max and percentile profiling, for the `ap_fixed<B,I>` format table |
| `phase2a_sweep.py`, `phase2a_collate.py`, `phase2a_mcnemar.py` | the activation-precision sweep and its paired tests |
| `sweep_quantized.py`, `collate_pareto.py` | the weight bit-width sweep and its Pareto collation |
| `inventory_runs.py` | regenerates the run table from the result CSVs |

**EAF drivers** — the `eaf_*.sh` scripts run on the Fermilab EAF GPU pods
(`eaf_run_ladder.sh`, `eaf_run_grid.sh`, `eaf_run_20M.sh`, `eaf_run_matched.sh`,
`eaf_teacher_selection.sh`, `eaf_rescore_ladder.sh`). Compute-heavy runs happen
there; results are pulled back manually.

**Notebooks**

| notebook | what it shows |
|---|---|
| `analysis_notebooks/EXPERIMENTS_LOG.ipynb` | the data-volume ladder and matched-capacity results, with figures |
| `analysis_notebooks/failure_case_explorer.ipynb` | per-shot failure analysis — error chains rendered in Crumble, with lattice position enrichment |
| `analysis_notebooks/baseline_mwpm.ipynb` | the MWPM threshold baselines across d and p |
| `QUANTIZATION_EXPERIMENTS.ipynb` | the quantization sweep write-up, generated by `build_quant_notebook.py` |

Notebooks are committed with their outputs, so results and figures are readable on
GitHub without running anything.

## Results

`docs/RUN_LOG.md` is the authoritative ledger: one entry per run with date, git SHA,
command, host, and result. Nothing counts as a real result there without the git
SHA, the pool generation seed, and the saved weights all pinned. Result files are
append-only and carry their pool directory in the filename.

Supporting notes are in `experiment_log/docs/` — `QUANTIZATION_SCHEME.md` for the
exact quantizer convention and the sign-bit subtlety, and
`RCNN_d5_r3_ladder_REFERENCE.md` for the data-volume ladder.
